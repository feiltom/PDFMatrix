# PDFMatrix — @feiltom/pdfmatrix

Repository: https://github.com/feiltom/PDFMatrix

Open-source alternative to `@pdftron/pdfnet-node`, with **the same API** (`PDFNet.PDFDoc`,
`getPageIterator`, `TextExtractor`, `Stamper`, `Field`, annotations…) and a **Rust** core exposed
to Node through napi-rs.

- No C/C++ code in the project: the core is Rust (`lopdf`, `hayro`, `ttf-parser`, `regex`, `image`).
- Permissive licenses only (MIT / Apache-2.0); no AGPL dependency.
- No license key: `PDFNet.runWithCleanup(main, key)` accepts the key and ignores it.
- Prebuilt binaries: **linux-x64** and **linux-arm64** (glibc).

```js
import { PDFNet } from '@feiltom/pdfmatrix';

async function main() {
  const doc = await PDFNet.PDFDoc.createFromFilePath('form.pdf');
  doc.initSecurityHandler();
  await (await doc.getField('name')).setValueAsString('Ada Lovelace');

  const stamper = await PDFNet.Stamper.create(PDFNet.Stamper.SizeType.e_relative_scale, 0.5, 0.5);
  await stamper.setRotation(45);
  await stamper.setOpacity(0.3);
  await stamper.stampText(doc, 'CONFIDENTIAL', await PDFNet.PageSet.createRange(1, await doc.getPageCount()));

  await doc.flattenAnnotations();
  await doc.save('out.pdf', PDFNet.SDFDoc.SaveOptions.e_remove_unused);
}
PDFNet.runWithCleanup(main).then(() => PDFNet.shutdown());
```

## Development (everything runs in podman)

Nothing gets installed on the host: Rust, Node and the tests run in the `dev` image.

```sh
make dev-image     # Rust (x64 + arm64 targets) + Node 22 image (once)
make install       # npm install (into a podman volume)
make build         # addon for the VM's architecture + TypeScript
make build-all     # x64 and arm64 addons (napi-rs cross-compilation) + TypeScript
make test          # node:test suite
make test-all      # suite + Office/HTML conversions (starts Gotenberg)
make test-amd64    # suite against the x64 binary (emulated on an ARM Mac)
make test-arm64    # suite against the arm64 binary
make examples      # examples/run-all.mjs -> ./out
make shell         # interactive shell in the container
make image         # self-contained image: build + tests (what the CI runs)
```

Podman volumes: `pdfnet-node-modules`, `pdfnet-cargo-registry`, `pdfnet-target`.

## CI (GitHub Actions)

`.github/workflows/build.yml`:

1. **build** — matrix `ubuntu-24.04` (x64) and `ubuntu-24.04-arm` (arm64): each architecture is
   built **and tested on its own CPU**, with podman and the same `Containerfile` as locally
   (`podman build --target test`, then `npm test`). Gotenberg is started alongside so that Office/HTML
   conversions are tested too.
2. **package** — gathers both `.node` binaries and runs `npm pack` (artifact `npm-package`).
   On a `v*` tag, creates a GitHub release with the tarball and the binaries.

> The `ubuntu-24.04-arm` runners are free for public repositories. For a private repository
> without ARM runners, build both architectures on x64 with `npm run build:all`
> (cross-compilation) and test arm64 under QEMU (`docker/setup-qemu-action`).

Appearances (annotations, fields) are generated in Rust: borders, dashes, colors, opacity,
multiply blending for highlights, line wrapping, alignment, comb/password/multiline fields,
list boxes with the selection shown, check marks and radio buttons.

### Phase 3 — security

| PDFNet class | Implemented |
|---|---|
| `SecurityHandler` | `createDefault` (AES-256), `create(AlgorithmType)`: RC4-40, RC4-128, AES-128, AES-256 (R2/R3/R4/R6); user/owner passwords, `setPermission/getPermission`, `getKeyLength`, `getEncryptionAlgorithmID`, `isAES/isRC4` |
| `PDFDoc` | `setSecurityHandler`, `getSecurityHandler`, `removeSecurity` (encryption is **kept** by default when re-saving an encrypted document), **incremental save** `SDFDoc.SaveOptions.e_incremental` (encrypted documents included) |
| Signatures | `createDigitalSignatureField`, `SignatureWidget.createWithDigitalSignatureField`, `DigitalSignatureField` (`signOnNextSave` / `FromBuffer` from PKCS#12, `setReason/Location/ContactInfo`, `setSubFilter` adbe.pkcs7.detached or ETSI.CAdES.detached, getters, `verify`), `getDigitalSignatureFieldIterator`, `verifySignedDigitalSignatures` |
| Verification | `VerificationOptions` (trusted certificates DER/PEM, `enableTrustVerification`), `VerificationResult` (document / digest / trust / modification statuses, algorithm, embedded certificates) |
| Redaction | `Redactor.redact` + `redactionCreate` (overlay color, border, overlay text, negative mode), `RedactionAnnot` + `PDFDoc.applyRedactions()` |

**Signatures**: RSA (PKCS#1 v1.5) and ECDSA P-256/P-384 keys from a PKCS#12, CMS SignedData with
the certificate chain, `signingTime`, ESS `signingCertificateV2` (PAdES B-B), visible appearance
("Digitally signed by…"). Signing happens through an incremental save, so earlier signatures stay
valid (countersignatures). Validated independently with poppler `pdfsig`, as well as
`openssl cms -verify -cades` for CAdES.

**Redaction**: text is removed glyph by glyph (the remaining text keeps its exact position),
image pixels under the area are blanked (raw/Flate/JPEG 8-bit) or the image is removed, vector
paths entirely inside the area are dropped, Form XObjects (stamps, etc.) are processed
recursively, and annotations under the area are removed.

```js
// Sign
const field = await doc.createDigitalSignatureField('Approval');
await page.annotPushBack(await PDFNet.SignatureWidget.createWithDigitalSignatureField(doc, rect, field));
await field.setReason('Approval');
await field.signOnNextSave('signer.p12', 'password');
await doc.save('signed.pdf', PDFNet.SDFDoc.SaveOptions.e_incremental);

// Verify
const opts = await PDFNet.VerificationOptions.create();
await opts.addTrustedCertificateUString('ca.pem');
await doc.verifySignedDigitalSignatures(opts); // PDFDoc.SignaturesVerificationStatus.e_verified

// Redact
const r = await PDFNet.Redactor.redactionCreate(1, new PDFNet.Rect(72, 650, 300, 670), false, 'REDACTED');
await PDFNet.Redactor.redact(doc, [r], { positive_overlay_color: await PDFNet.ColorPt.init(0, 0, 0) });
```

### Phase 4 — conversion

| PDFNet class | Implemented |
|---|---|
| `Convert` | `officeToPdf(doc, path or bytes, options)`, `toPdf(doc, path)` (PDF → copied pages, images → one page per image, HTML → Chromium, everything else → LibreOffice), `fromImage(doc, image, dpi)`, `officeToPdfDoc(input)` |
| `OfficeToPDFOptions` | `setGotenbergUrl`, `setLandscape`, `setPageRanges`, `setPassword`, `setExportFormFields`, `setFileName` (in-memory input; the format is otherwise detected), `setTimeout` |
| `HTML2PDF` | `insertFromUrl`, `insertFromHtmlString`, `setPaperSize`, `setMargins`, `setLandscape`, `setPrintBackground`, `convert(doc)` |

PDFs and images are converted **locally** (Rust core). Office (docx, xlsx, pptx, odt, rtf, txt,
csv…) and HTML go through **[Gotenberg](https://gotenberg.dev)** 8.37 (MIT, LibreOffice +
Chromium) running **in its own container**: the Node image stays light and LibreOffice is never
loaded into your process. URL: option `setGotenbergUrl`, otherwise `$GOTENBERG_URL`, otherwise
`http://localhost:3000`.

```sh
make gotenberg        # starts Gotenberg on the "pdfnet" podman network (port 3000)
make test-all         # full suite, Office/HTML conversions included
make gotenberg-stop
podman compose up     # example deployment: compose.yaml (app + gotenberg)
```

```js
const doc = await PDFNet.PDFDoc.create();
await PDFNet.Convert.officeToPdf(doc, 'report.docx', null);
await doc.save('report.pdf', PDFNet.SDFDoc.SaveOptions.e_remove_unused);
```

OCR is not included (not needed).

### DocGen — .docx templates (`Convert.createOfficeTemplateWithPath`)

Same flow as Apryse DocGen:

```js
const template = await PDFNet.Convert.createOfficeTemplateWithPath('invoice.docx', new PDFNet.OfficeToPDFOptions());
const keys = await template.getTemplateKeysJson();                 // expected keys (JSON)
const pdf = await template.fillTemplateJson(JSON.stringify(data)); // PDFDoc (through Gotenberg)
await template.fillTemplateJsonToOffice(JSON.stringify(data), 'invoice-filled.docx');
const warnings = await template.getErrorString();                  // missing values…
```

| Syntax | Effect |
|---|---|
| `{{name}}`, `{{client.address.city}}`, `{{this}}` | value (dotted path, scoped inside loops; `\n` → line break) |
| `{{loop lines}}` … `{{endloop}}` | repeats **table rows** (tag inside a row), **paragraphs** (tags in their own paragraphs) or **runs** (inside a paragraph); nested loops; `{{loop_number}}` / `{{loop_index}}` |
| `{{if cond}}` … `{{elif cond}}` … `{{else}}` … `{{endif}}` | conditions: `== != > < >= <=`, `&& \|\| !` (or `and or not`), parentheses, numbers, strings `"…"` (Word's typographic quotes accepted) |
| `{{logo}}` + `{"logo": {"image_url": "file.png" \| "https://…" \| "data:…", "width": 64, "height": 64}}` | inline image (size in points; aspect ratio kept if only one dimension is given) |

Tags that Word splits across several runs (formatting, spell checking) are reassembled
automatically. Body, headers, footers and notes are processed. Filling is done in Rust (the
`.docx` is never opened by LibreOffice); only the PDF output goes through Gotenberg.

Differences from Apryse: no formatting functions (dates, numbers): numbers are written as in
the JSON; no rich text / HTML values; loops/conditions spanning several cells of the same row
are not supported (put the tags in the same row, or in separate paragraphs/rows).

## Migrating from `@pdftron/pdfnet-node`

Without changing any code, by aliasing the package name:

```json
"dependencies": { "@pdftron/pdfnet-node": "npm:@feiltom/pdfmatrix@^0.1.0" }
```

Validated on a real API project (Fastify, TypeScript 6, CommonJS): `tsc` without errors and
its PDF helpers run for real: Office/image/PDF → PDF conversion, page splitting, thumbnails,
DocGen, XFDF validation and merge, merge with rotation, optimization. The license key is
ignored and Gotenberg must be reachable (`GOTENBERG_URL`) for Office/HTML conversions.

## Known limitations

- `e_linearized` accepted but ignored (no linearization).
- Signatures: no RFC 3161 timestamp, no LTV (OCSP/CRL), no revocation or validity-period check during verification; changes made after a signature are reported as `e_has_allowed_changes` without analysis (no DocMDP). Signing an **encrypted** document is not supported yet.
- Redaction: vector paths only partially covered stay in place (hidden by the overlay), shadings are not touched, Type3 fonts and non-Identity CMaps use approximate metrics; JBIG2/CCITT/16-bit images are removed entirely as soon as they are touched.
- A form field with a single widget is written merged (field + widget in one dictionary), like Acrobat/PDFNet; it is split automatically when a second widget is added.
- Native calls are synchronous (a large render blocks the event loop while it runs).
- Embedded TrueType fonts: full embedding (no subsetting), so ~750 KB for DejaVu Sans.
- Forms: no JavaScript (formatting, calculations, validation) and no rich text.
  `setFlag` and the others regenerate the appearance; existing checkbox/radio appearances are kept.
- Annotations: no creation of FileAttachment/Sound/Movie/3D/Caret (they are still read as `Annot`);
  `showsOnScreen/showsOnPrint` (optional content) is ignored by the Stamper.
- The low-level SDF/`Obj` API is not exposed publicly (used internally).
- Text: reading order = content stream order; approximate glyph boxes (0.8/-0.2 em).
- Rendering (hayro): no knockout groups or isolation.
